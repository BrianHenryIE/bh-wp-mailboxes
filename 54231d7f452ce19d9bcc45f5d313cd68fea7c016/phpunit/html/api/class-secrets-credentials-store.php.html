2/**
3 * Credentials store backed by the WordPress Secrets API.
4 *
5 * Talks directly to a `WP_Secrets_Provider` (by default `WP_Secrets_Libsodium_Provider` over the options
6 * store) built from the library's own copy of the API's classes, loaded from vendor by
7 * {@see \BrianHenryIE\WP_Mailboxes\Secrets_API_Loader}. It deliberately never calls `wp_get_secret()` etc.:
8 * those resolve their provider through `$GLOBALS['wp_secrets_store']` / `wp_secrets_keyring` /
9 * `wp_secrets_provider`, which a site's `secrets.php` drop-in sets, and this library's credentials should
10 * not be redirected by it. (Consumers prefix the copy's names at build time.)
11 *
12 * One secret per account, named `{plugin-slug}/{accounts-post-type}-{email address}` (e.g.
13 * `my-plugin/my_plugin_accounts-inbox-at-example-com`), holding the credentials' own JSON representation
14 * ({@see Account_Credentials_Interface::jsonSerialize()}): a `type` key (`imap` or `gmail`) plus the
15 * credential fields, rebuilt by the matching class's `from_array()`. The Secrets API encrypts the value
16 * at rest; the name is readable, so listing a plugin's secrets shows which accounts have credentials.
17 *
18 * @package brianhenryie/bh-wp-mailboxes
19 */

108     *
109     * Secret names allow only lowercase alphanumerics, hyphens and underscores in each of the two
110     * segments, so every part is lowercased and normalised, with the address's `@` written as `-at-`
111     * (`Inbox@Example.com` becomes `inbox-at-example-com`). Addresses that differ only in characters
112     * outside that set (e.g. `a.b@` and `a-b@`) would share a name; the Secrets API rejects names over
113     * 172 characters, which the store reports as a failed save.
